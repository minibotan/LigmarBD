# LigmarBD — актуальный контекст и ближайший план

## Что уже работает

- Главная страница с предупреждением о фанатском статусе проекта.
- «Мои персонажи»: отдельные персонажи и слоты для каждого класса и мира, экипировка, характеристики, пресеты, изученные навыки и общие активные баффы.
- Каталог T4, T6 и легендарных T8-предметов, заточка, дополнительные свойства и камни.
- DPS-трекер: персонажи, цели, ротации, сохранённые пресеты, баффы, попадания, криты, броня, DOT, бег и поиск цели.
- Библиотека T4/T6/T8 с локальным прогрессом, уровнями свойств, чертежей и коллекции.
- Мастерская с уровнями мастеров, скидками и расходами материалов.
- Миры: локации, гекс-карты, группы противников и карточки мобов.
- Гайды как отдельный раздел с карточками и самостоятельными страницами.
- Локальные сохранения, экспорт/импорт персонажей и публикация через GitHub Pages.

Google Drive-синхронизация остаётся будущим этапом. Локальная версия должна продолжать работать независимо от неё.

## Текущая работа

Страница уже создана. Перед завершением нужно:

- выполнить финальную визуальную проверку.

### 2. Гайд по заточке

Страница и модель расчёта уже созданы. Сейчас в ней есть:

## Следующий этап: структура файлов сайта

Рефакторинг выполняется после завершения двух гайдов, отдельным этапом без изменения поведения.

Основные задачи:

1. Отделить исходники сайта от публикуемой папки. Сейчас `site/dist` одновременно содержит исходный JavaScript, стили, данные и готовую публикацию.
2. Разделить крупный `app.js`: роутер/загрузка приложения, главная, персонажи, экипировка и навыки.
3. Разделить общий `styles.css` по разделам или компонентам; `worlds.css` уже частично отделён.
4. Сделать единый реестр маршрутов и страниц вместо цепочки проверок `location.hash`.
5. Вынести общие UI-функции: таблицы, форматирование, экранирование, подсказки, карточки предметов.
6. Убрать ручные версии `?v=...` из импортов и загрузки данных, заменив их одной версией сборки или автоматическим хешированием.
7. Разделить справочные данные, пользовательское состояние и миграции сохранений.
8. Обновить документацию и проверки после перемещения файлов.

## Ограничения работы

- Сначала завершить пользовательские изменения текущей фичи, затем коммитить.
- Не публиковать и не проверять GitHub Pages без прямой команды пользователя.
- При переносе файлов не менять формулы и поведение одновременно со структурой.
- Не включать `work/library-progress-2026-10-02.json` в коммиты: это отдельный пользовательский файл прогресса.
